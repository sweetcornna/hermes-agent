# T4 — QQ 协议端迁至家宽住宅网络：迁移 runbook

轨道/档位：Claude / opus（迁移方案设计，隐性约束极多，一步做错会把线上 QQ 打死并触发风控加码）

## 背景（自包含，你看不到主线程上下文）

仓库 `/Users/cornna/project/hermes-agent`。这套系统用一个**个人 QQ 号**（`2952532060`）
作为 AI agent 的对话通道，经 NapCat（真 QQ 客户端注入）暴露 OneBot v11 正向 WebSocket，
Hermes 作为**客户端**拨过去。

### 现状拓扑

**先自己读 `docs/migration-corlinman/H1-napcat-hardened.md` 的 §4「最终生产拓扑」把表抄准**，
下面是概要，不要拿概要当事实：

- NapCat 跑在 SSH 别名 `cornna-cn` 上，`napcat.service` + `mlikiowa/napcat-docker:v4.18.19`
- 设备身份卷 `cornna-cn:/opt/napcat/ntqq` → 容器 `/app/.config/QQ`（约 173 MiB、1691 个文件）
- OneBot 在 `cornna-cn:127.0.0.1:3011` → 容器 `3001`，不向公网开放
- `corlinman-prod:onebot-tunnel.service` 把 `corlinman-prod:127.0.0.1:3011` 经 SSH 转发过去
- Hermes 跑在 `corlinman-prod`，连 `ws://127.0.0.1:3011`

### 要解决的问题

H1 §3 用 3035 条心跳测出：**连续在线区间约 2 小时整**，两次都是
`[KickedOffLine] 你的账号当前登录已失效`，且快速登录票据同时失效，每次都要人工扫码。
两次空窗 9.7 h 和 11.7 h。

判断：`cornna-cn` 是**阿里云机房 IP**，而 `2952532060` 是 2026-08-28 才启用的**新号**。
「~2 小时固定会话寿命」是低信任账号的症状，机房 IP 上不会自己改善。

### 本任务的决定（已由用户批准，不要重新论证）

把 NapCat **下沉到用户家里一台 7×24 常开的小主机**（家宽住宅 IP），云端 Hermes 不动。

注意 H1 §4.1 有一条「出口 IP 保持不变」的记录，理由是「不建议改走**境外代理节点**：
对国内号更可疑」。**那条否决的是境外代理，不是国内住宅 IP**，与本决定不冲突。
你的 runbook 里要写明这个区分，免得后来人以为在违反 H1。

## 目标

写一份**人能照着一步步做完**的迁移 runbook。你**不执行**，只写文档。

## Runbook 必须覆盖的内容

### 1. 架构与隧道方向

推荐架构（你要论证它对，或提出更好的并说明理由）：

```
家里小主机（住宅 IP，7×24）
  napcat.service + mlikiowa/napcat-docker:v4.18.19
    └ OneBot v11 正向 WS → 本机 127.0.0.1:3001
         └ autossh -R 反向隧道（家里主动发起）
              └ corlinman-prod:127.0.0.1:3011
                   └ hermes.service 连 ws://127.0.0.1:3011（配置一个字不用改）
```

要点：
- **镜像双架构已确认**：Docker Hub 上 `mlikiowa/napcat-docker:v4.18.19` 同时有 amd64 和 arm64，
  所以 Mac mini（Apple Silicon）、ARM NAS、x86 小主机都能跑。runbook 里要给出**确认当前机器架构**
  的命令，以及拉取时如何确认拿到的是对的那个。
- **隧道必须由家里发起**（`-R`），因为家宽通常没有公网 IP 或处在 CGNAT 后面。
- 这样设计的一个关键好处：Hermes 侧 `ONEBOT_WS_URL` 仍然是 `ws://127.0.0.1:3011`，
  **一个字都不用改**。这同时避开了一个已知的坑：`.env` 的 `ONEBOT_WS_URL` 会覆盖
  `config.yaml` 的 `platforms.onebot.extra.ws_url`，改端点必须两处都改
  （记录在 `docs/migration-corlinman/00-PLAN.md` 约 1959 行）。runbook 要写明这一点。
- 现有的 `corlinman-prod:onebot-tunnel.service` 是**反方向**的（prod 主动连 cornna-cn）。
  迁移后它必须停掉，否则两条隧道抢同一个本地端口 3011。这一步不能漏。

### 2. 设备身份：不要复制

**硬约束**：不要把 `cornna-cn:/opt/napcat/ntqq` 复制到新机。理由有两条，都要写进 runbook：
- H1 §4.1 明令设备身份目录「绝不能删、复制到并行实例或重建」
- 跨机复制实测无效：曾经把 `login.enc` + `login.db` 从香港机原样搬到广州机，
  QQ 仍然 `loggedIn:false`，腾讯把凭据绑了设备/地域，必须重新扫码

结论：**新机 = 新设备，扫一次码，之后永不再迁**。runbook 要把「永不再迁」写成一条醒目的约束。

### 3. 单实例互斥（这一步做错会直接触发风控）

同一个 QQ 号**绝不允许在两个 NapCat 实例并行登录**（H1 里是硬禁令）。
runbook 必须给出严格的顺序和**可验证的检查点**：先怎么停旧的、怎么确认真的停了
（端口检查怎么做、容器状态怎么看、systemd 怎么确认不会自己拉起来）、然后才允许新机登录。

注意 `napcat.service` 的 `Restart=` 和 Docker 的 `restart=` 都可能把容器拉回来，
两者都要处理。H1 §10 提到权威机的 unit 当时还是 `Restart=always`。

### 4. 新机的 systemd / 容器配置

照抄 H1 §4.1 和 §5 里已经验证过的加固参数，包括但不限于：
- `StartLimitIntervalSec` / `StartLimitBurst` **必须放 `[Unit]` 段**（放 `[Service]` 会被 systemd 静默忽略）
- systemd `Restart=on-failure` + 退避，Docker 明确 `restart=no`，避免双重无限重启
- 镜像要钉 digest 而不只是 tag
- config 目录 700、文件 600
- **不要配置 `NAPCAT_QUICK_PASSWORD`**。H1 §4.1 明令只用官方 `ACCOUNT` 快速登录契约，
  失败后转人工扫码；反复密码登录会让风控加码，且被踢后密码登录会阻塞在短信验证上。

### 5. 隧道的失败策略

照抄 H1 §8.2 已经修正过的参数并说明理由：`RestartSec=30`、`StartLimitIntervalSec=0`
（否则持续断网会耗尽启动额度后永久停在 failed，必须人工 reset）、SSH 要加 `ConnectTimeout`。
另外家宽会掉线重拨，隧道要能自愈 —— 这一点比机房环境更重要，给出具体配置。

### 6. 验收

只用**短生命周期只读探针**：连 `ws://127.0.0.1:3011`，只调 `get_status` 和 `get_login_info`，
要求 `online=true`、`good=true`、`get_login_info` 返回的 UIN 是 `2952532060`。
token 要从进程内读取，不能出现在命令行或输出里。
**不要发任何测试消息。**

### 7. 回滚

云上的容器、设备目录、config 全部保留不删。给出完整回滚步骤和它的代价
（回滚也要重新扫码 —— 这一点要讲清楚，别让人以为回滚是免费的）。

### 8. 迁移后的观测

H1 §10 自己标注「~2 小时被踢」样本仅 2 次，是线索不是定论。
runbook 最后要写明：迁移后必须继续采集连续在线区间，**2 周后对比迁移前后的中位会话时长**，
否则无法判断这次迁移到底有没有用。给出要记录哪些字段。

## 项目约定

- 设计必须落盘为 md 工件。
- runbook 面向**人手工执行**，每一步要有命令、预期输出、以及「如果不是预期输出该怎么办」。
- 破坏性步骤前必须有备份指令，备份路径按项目惯例 `<path>.bak-pre-<change>-<UTC时间戳>`。

## 禁止事项

- ⛔ **不要执行迁移**。只写文档。
- ⛔ **不要 SSH 到任何远程主机**（`cornna-cn`、`corlinman-prod` 等一律不碰）。
  你要写的是给人执行的步骤，不是自己去跑。
- ⛔ 不要设计任何自动重启、自动重登、自动密码登录。
- ⛔ 不要在文档里写任何 token / 密码 / cookie 的**值**。
- ⛔ 不要修改 `plugins/`、`gateway/`、`tests/` 下任何文件。
