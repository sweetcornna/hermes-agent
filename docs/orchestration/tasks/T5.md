# T5 — 审计 T4 家宽迁移 runbook

轨道/档位：GPT / gpt-auditor（只读。Claude 轨道的关键交付必须有异构第二意见）

## 你的角色

只读审计员。**⛔ 禁止改动任何文件**（除了你自己的输出文件）。Bash 仅用于 `git diff`、`git status`、
只读检查。**⛔ 不要 SSH 到任何远程主机。**

## 被审对象

`docs/orchestration/tasks/T4-home-migration-runbook.md` —— 一份把 QQ 协议端（NapCat）从
阿里云机房迁到家宽住宅网络的手工执行 runbook。

## 背景（自包含）

这条链路驱动一个**真实的个人 QQ 号**（`2952532060`）。做错的后果不是「测试失败」，
而是**账号被腾讯封禁或长时间掉线**，且部分动作不可逆。所以审计要按「这会不会把号搞死」来审，
不是按代码风格审。

## 必须逐条核验的硬约束

去 `docs/migration-corlinman/H1-napcat-hardened.md` 和 `docs/orchestration/decisions.md`
读原文，然后逐条检查 runbook 是否遵守：

1. **绝不写后端配置** —— 永不调 NapCat WebUI 的 `/api/OB11Config/SetConfig`（同机可能有别的写者）
2. **设备身份目录绝不能删、绝不能复制到并行实例、绝不能重建**
3. **同一 QQ 账号绝不允许在两个实例并行登录**
4. **只能有一个生命周期管理者**（systemd `Restart=` 与 Docker `restart=` 不能同时生效）
5. **不得设计任何自动重启 / 自动重登 / 自动密码登录**（`napcat-watch`、`qq-watchdog` 都是被
   有意 masked 的，理由是「第二个消耗登录尝试的生命周期管理器」会让风控加码）
6. **不使用 `NAPCAT_QUICK_PASSWORD`**
7. **互斥不得用 `Conflicts=`** —— 该机曾因 `Conflicts=` + `Restart=` 陷入互杀循环，
   现用 `bin/preflight` + `flock`
8. **`StartLimitIntervalSec` / `StartLimitBurst` 必须放 `[Unit]` 段**（放 `[Service]` 被 systemd 静默忽略）
9. 验收只用短生命周期只读探针（只调 `get_status` / `get_login_info`），**不发测试消息**
10. token / 密码 / cookie 的**值**不得出现在文档、命令行或输出里
11. 破坏性步骤前必须有备份指令

## 另外必须检查的（这些最容易漏）

- **`corlinman-prod:onebot-tunnel.service` 必须被停掉**：迁移后家里会建一条反向隧道占用
  `corlinman-prod:127.0.0.1:3011`，而现有的 `onebot-tunnel.service` 也正持有那个端口。
  runbook 有没有显式处理这个端口冲突？漏了会导致隧道起不来且症状难查。
- **`napcat-native.service` 当前是 `disabled` 但 active**。runbook 的「停旧实例」步骤有没有
  考虑到：`systemctl stop` 后进程树（`dbus-run-session → AppRun → qq → qq`）可能有残留？
  有没有给出验证进程真的死透的命令？
- **回滚也要重新扫码**。runbook 有没有把这一点讲清楚，还是暗示回滚是免费的？
- **有没有 baseline 采集**：迁移前如果不先记录当前的连续在线时长，迁移后无法判断有没有用。
- **每一步有没有「预期输出」和「不是预期输出怎么办」**，还是只有命令。
- **架构判断是否成立**：反向隧道方向（家里主动 `-R`）对不对？家宽 CGNAT/无公网 IP 的
  前提有没有讲？Hermes 侧 `ONEBOT_WS_URL` 是否真的不用改？

## 输出要求

按**严重度排序**（致命 / 高 / 中 / 低），每条含：
- 问题是什么
- 在 runbook 的哪一节 / 哪一行
- 违反了上面哪条硬约束（或属于「最容易漏」里的哪项）
- **具体的修改建议**（不要只说「应该注意」）

**没发现问题也要写明**：写清楚你检查了哪些范围、用了什么方法，以及为什么认为没问题。
⛔ 不要因为文档写得流畅完整就放松——重点找「声称做了但实际没有可执行步骤的」、
「看着安全实际会触发并行登录的」、「顺序写反了的」。

## 输出格式

Markdown → `docs/orchestration/audits/T4.md`。完成标志：该文件存在，含按严重度排序的问题清单
（或明确的「未发现问题 + 检查范围」），且 11 条硬约束逐条有核验结论。
