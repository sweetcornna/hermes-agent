# T2 — OneBot 限流开关：语义梳理与推荐值

轨道/档位：GPT / gpt-luna-exec（规格明确，读代码 + 写配置样板）

## 背景（自包含）

仓库 `/Users/cornna/project/hermes-agent`。`plugins/platforms/onebot/` 是接**个人 QQ 号**的适配器
（经 NapCat 的 OneBot v11）。个人号发言过频会触发腾讯风控（禁言、冻结、封号），
所以限流是**账号安全设施**。

现状：适配器实现了四套语义不同的限流机制，代码和测试都齐了，但**默认值全是 `0`（即全部关闭）**。

## 目标

把这四套机制的语义讲清楚，给出推荐值，并写进配置样板。

## 具体要做的事

1. 读实现，把四套机制的**准确语义**搞明白（不要靠猜，要引代码行号）：
   - `plugins/platforms/onebot/rate_limit.py`（`TokenBucket` 与 `SlidingWindowCounter`，
     注意文件头注释解释了为什么硬上限用滑动窗口而不是令牌桶）
   - `plugins/platforms/onebot/router.py`（令牌桶的判定点，注意它在闸门**之后**才扣配额）
   - `plugins/platforms/onebot/adapter.py` 约 2831-2849 行（群硬发言上限的挂载点）
   - `plugins/platforms/onebot/adapter.py` 约 1640-1675 行（env 接线）
2. 对这四个键各写一段：`ONEBOT_RATE_LIMIT_GROUP_PER_MIN`、`ONEBOT_RATE_LIMIT_SENDER_PER_MIN`、
   `ONEBOT_GROUP_REPLY_COOLDOWN_SECS`、`ONEBOT_GROUP_RATE_LIMIT_WINDOW_MINUTES` +
   `ONEBOT_GROUP_RATE_LIMIT_MAX_MESSAGES`。每段含：
   - 它到底限的是什么（入站还是出站？每群还是每人？令牌桶还是硬窗口？）
   - `0` 的语义是「关闭」还是「全部拒绝」——**必须去代码里确认，不要假设**
   - @提及能不能绕过它
   - 它与「主动发言」是否共用同一份预算
3. 给推荐值。约束条件：
   - 群回复目前默认关闭（`ONEBOT_GROUP_REPLIES_ENABLED` 默认 `false`）
   - 主窗口是**与单个 QQ 用户的私聊**，那是低频高价值通道，不能被限死
   - 目标是「群一旦打开，发言频率看起来像人而不像机器人」
   - 代码注释里已经出现过一个生产建议值（3 分钟 / 5 条），找出来并说明你是否同意
4. 把推荐值写进配置样板 `docs/migration-corlinman/B3-hermes-config.yaml.example` 的
   `platforms.onebot` 段（约 159 行起）。**保持该文件既有的注释风格和缩进。**
   改之前先备份：`cp <file> <file>.bak-pre-T2-$(date -u +%Y%m%dT%H%M%SZ)`
5. 跑 `python -m pytest tests/gateway/test_onebot_rate_limit.py -q`，如实记录输出。
